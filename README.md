# 全身寿司打（開発版）

Webカメラの33点姿勢ランドマークで、寿司ネタのROMAJIを一文字ずつ全身ポーズで入力する60秒のブラウザゲームです。たとえば「えび」は `E → B → I` を順に成功させると一皿完成です。明るい寿司屋風のゲーム盤で、カメラ・目標ポーズ・得点・寿司レーン・ランキングを一画面に表示します。

```bash
npm install
npm run dev                 # ゲーム＋ローカルD1のランキングAPI
npm run dev:ui              # UIのみ（ランキングAPIなし）
npm test
npm run test:api            # 実際のローカルD1を使うAPI回帰テスト
npm run typecheck
npm run build
```

## ローカルD1を含めて動かす

`npm run dev` がmigration、静的ビルド、Worker/D1を `.local-state/` 共有で起動します。初回のカメラ姿勢モデル読み込みにはMediaPipe CDNへの通信が必要です。

本番設定は [`wrangler.jsonc`](./wrangler.jsonc) にあり、ランキング専用のD1 `zenshin-sushida-rankings` を束縛しています。公開は `npm run deploy:production` で、静的ビルド、本番D1 migration、Worker公開を順に実行します。開発は必ず `wrangler.local.jsonc` を使うため、ローカル専用IDを本番へ使いません。

### GitHub連携による自動公開

Cloudflare Workers Buildsでは、GitHubの `main` へのpushを公開トリガーにします。Cloudflare DashboardでWorker **zenshin-sushida** の **Settings → Builds → Connect** を開き、GitHubリポジトリを選択してください。設定値は次のとおりです。

| 項目 | 値 |
| --- | --- |
| Production branch | `main` |
| Build command | `npm run build` |
| Deploy command | `npm run d1:migrate:remote && npm run deploy:worker` |
| Preview command | `npx wrangler preview --config wrangler.jsonc` |

Workers Builds上のWorker名と`wrangler.jsonc`の`name`はどちらも `zenshin-sushida` にします。D1 migrationは適用済みのものを再実行しないため、各公開前に安全に実行できます。

## 一枚の2Dゲーム画面

タイトル、操作ボタン、カメラ映像、骨格ガイド、採点HUD、結果、ランキングは、一枚のCanvas 2Dゲーム盤に描画します。ローカルの筆文字タイトルと、8種類の描き下ろし寿司皿アトラスをCanvas上でトリミング表示し、現在の大皿・ROMAJIレタートラック・次の皿を同じゲーム状態に連動させます。外部サイトのロゴやテクスチャは使いません。

カメラ映像は同じ2D canvas内で、元の採点座標系を変えずに表示だけを一度ミラーします。名前入力だけは日本語IMEのため、同じ論理レイアウトに配置するネイティブ入力を使います。描画は最大30fps、DPRは1.5までで、タブ非表示・画面外ではループを止め、`prefers-reduced-motion`では状態変更・リサイズ時だけ更新します。Canvas 2Dが利用できないときは明示的な案内を表示します。

## 判定と得点

カメラ映像はCanvas 2Dの描画変換で一度だけ左右反転し、骨格はMediaPipeの生座標を `displayBonePoint` の `1 - x` で同じ映像表示枠へ写します。ゲーム盤全体をCSSで反転しません。判定時は腰の中点からのX相対座標を一度反転し、テンプレートと同じ「鏡像ビューでは右が正」の正規化座標へ変換します。左右の関節番号は入れ替えないため、腕を交差しても関節の意味は保たれます。続いて肩幅を尺度にし、映像アスペクト比を補正してからEMA（前フレーム0.7、現フレーム0.3）を掛けます。判定は関節位置35%、ひじ/ひざ角度と上下肢方向45%、左右対称も許す近傍中心線20%です。

しきい値は75%で、さらに目標文字が次点の文字より3ポイント以上高い状態を400ms連続で維持するとROMAJIの1文字が成功します。特に混同しやすいGでは4ポイント、Sでは5ポイント以上必要です。Gは左腕を低めの上フック、右腕を胸前の内向きに折る形にして、足をそろえます。似た文字で曖昧なときは、骨格表示とカメラ準備を維持したまま腕の向きを確認する案内を出します。単語の最終文字で一皿が完成し、完成皿数は文字成功数・得点とは別に表示します。フレーム間隔が180msを超えたり、姿勢ロスト・不一致ならホールドをやり直します。得点は `round(100 + 一致度×100 + min(コンボ,20)×12)`、スキップは現在の皿の残り文字を流してコンボを0にします。終了後は採点しません。タブを背景へ移す場合も60秒の時計は止めず、保持だけを無効化します。ROMAJIで使用する15種類の姿勢は人が無理なく取りやすい暫定セットで、実カメラでのチューニング前です。

## ランキング

Cloudflare D1のオンラインランキングです。通常カメラゲームだけがサーバー発行の一回限りセッションを得て登録できます。サーバーはイベント履歴から得点を再計算し、同一セッションにつき一行だけを原子的に保存します。未送信の結果を新しく保存できる期限はゲーム開始から15分です。送信中の二重操作や通信応答の取りこぼしでは、同じ正当なID・トークン・ルール設定に限り、保存済みの一行を期限後も成功として確認できます。この確認は再登録や得点変更を行いません。未送信の期限切れ・設定変更・登録情報を確認できない場合は新しいラウンドを始めてください。開発用シミュレーションは同じ正規化・マッチャー・ゲームエンジンを通りますが、ランキングAPIでは拒否されます。並び順は得点、解答数、最大コンボの降順、同値なら早い登録・ID順です。

開始前に入力したランキング名（空白を除いて1〜20文字）をそのラウンドに固定し、結果画面から登録します。入力欄は利便性のためブラウザの `localStorage` に次回用として記憶されます。登録ボタンを押した場合のみ、表示名・得点・文字成功数などの結果がD1ランキングへ保存されます。メニューの「デモを見る（自動入力）」は判定やレーン進行を見るための自動デモで、結果は必ずランキング対象外です。

クライアントから映像や生の姿勢列は送信・保存しません。カメラに対する本人性や改ざんを完全に証明する仕組みは未実装です。ゲームに影響するルール（時間、しきい値、保持時間、姿勢・得点版）は`rulesKey`で分離し、別版を同一ランキングに混ぜません。

寿司ネタは提供されたドット絵の12種類（あかがい・びんちょうまぐろ・えび・ほたて・いくら・まぐろ・生えび・ねぎとろ・さば・たこ・鉄火巻き・うに）のみで、同じシードのゲームでは全種類が一度ずつ出るまで同じネタを出しません。実カメラでの操作感と、実D1を使うランキング登録のE2E確認はまだローカル開発環境でのみ確認対象です。
